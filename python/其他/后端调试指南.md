# 后端调试指南

前端调用接口时，如何在后端工程中打断点。

核心思路：**用调试模式启动后端，而不是普通启动**。

---

## 一、PyCharm 调试运行（推荐）

项目自带 `.idea`，解释器为 `backend/.venv`，直接配一个运行配置即可。

### 1. 新建运行配置

右上角运行配置下拉 → **Edit Configurations…** → `+` → **Python**，按下表填写：

| 字段 | 值 |
| --- | --- |
| Name | `uvicorn-debug` |
| **Module name** | `uvicorn`（选 Module，不是 Script） |
| Parameters | `app.main:app --host 127.0.0.1 --port 8010` |
| Working directory | `.../book_management_system/backend` |
| Python interpreter | `backend/.venv/bin/python`（Python 3.14） |

### 2. 打断点

在 `app/books/router.py` 或 `app/books/service.py` 中，点行号左侧打红点，例如 `list_books()` 的第一行。

### 3. 启动并触发

点 **Debug**（小虫子图标）启动，然后刷新浏览器或输入搜索词，请求进来就会停在断点上。

---

## 二、关键注意点：调试时去掉 `--reload`

这是最容易踩的坑。

`--reload` 会让 uvicorn 启动**父进程监听文件、子进程真正跑应用**。PyCharm 默认只调试父进程，断点打在子进程里不生效（表现为断点是空心圈，永远不停）。

- **调试时**：参数里不要加 `--reload`
- **平时开发**：继续用 `--reload`，改代码自动重载

如果确实想带 reload 调试，可开启：

```
Settings → Build, Execution, Deployment → Python Debugger
  → Attach to subprocess automatically while debugging
```

但不如直接关掉 reload 稳定。

---

## 三、先停掉正在运行的 8010

终端里已有 uvicorn 占用 8010 时，调试实例会报 `Address already in use`。

```bash
lsof -tiTCP:8010 -sTCP:LISTEN | xargs kill
```

然后再在 PyCharm 里 Debug 启动。

## 四、临时方案：`pdb`

不想动配置时，在代码里插一行即可：

```python
def list_books(...):
    breakpoint()   # 程序执行到这里暂停
```

用**不带 reload** 的方式启动：

```bash
cd backend
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8010
```

前端一发请求，终端进入 pdb：

| 命令 | 作用 |
| --- | --- |
| `p 变量名` | 打印变量 |
| `n` | 执行下一行 |
| `s` | 进入函数 |
| `c` | 继续运行 |
| `q` | 退出调试 |

缺点：会阻塞整个服务，且没有图形化变量面板。

---

## 五、远程调试：debugpy

想在 VS Code 或其他编辑器调试时：

```bash
cd backend
.venv/bin/pip install debugpy
.venv/bin/python -m debugpy --listen 5678 -m uvicorn app.main:app --host 127.0.0.1 --port 8010
```

然后在编辑器中 attach 到 `127.0.0.1:5678`。

---

## 六、不用断点也能定位：看请求日志

后端已记录每个请求，日志位于 `/tmp/book_backend_8010.log`：

```bash
tail -f /tmp/book_backend_8010.log
```

可以看到：

```
INFO: 127.0.0.1:53962 - "GET /api/books?keyword=刘慈欣&page=1&page_size=20 HTTP/1.1" 200 OK
```

很多时候不用断点就能确认参数是否正确、是否返回 200。

## 常见问题

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 断点是空心圈，不生效 | 启动时带了 `--reload` | 调试时去掉 `--reload` |
| 启动报 `Address already in use` | 8010 已被占用 | `lsof -tiTCP:8010 \| xargs kill` |
| 点 Debug 后没有任何反应 | 没打成功断点 / 请求未命中该函数 | 检查断点位置与请求路径 |
| 找不到 `app` 模块 | 工作目录不对 | Working directory 设为 `backend/` |
| 改了代码要手动重启 | 调试模式没有 reload | 预期行为，重启调试即可 |
